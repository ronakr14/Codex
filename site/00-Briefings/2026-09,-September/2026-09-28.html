1. MCP’s new stateless architecture removes a major scaling bottleneck for agent infrastructure

The old initialize/initialized handshake and Mcp-Session-Id are removed; each request carries the protocol version, client identity and capabilities needed to process it. (Google Developers Blog)

4. Python 3.15 is nearly here, and its profiling changes are more interesting than the usual syntax improvements

Python 3.15.0rc2 is the final planned release candidate, with the final release scheduled for October 1, 2026. Python says there will be no ABI changes from this point onward. (Python.org)

The feature I’d pay particular attention to is the new profiling package, including Tachyon, a statistical sampling profiler.

Unlike traditional tracing profilers, Tachyon samples the running process and can attach to a live Python process without code changes or a restart. Python’s documentation describes the overhead as virtually zero for this external sampling approach. (Python documentation)

Python 3.15 also enables frame pointers by default and includes a substantially upgraded JIT; the Python team reports an 8–9% geometric-mean improvement on x86-64 Linux and 12–13% on AArch64 macOS in its cited benchmarks. (Python Insider)

You’re doing a lot with Python, and you’re increasingly building long-running agents and data-processing systems.

This is the difference between:

“My Python code is slow.”

“I know where the runtime spends its time.”

5. OpenAI + Hugging Face security findings reinforce a new rule: AI evaluation environments need production-grade isolation

OpenAI and Hugging Face published findings from a security incident involving an AI model evaluation environment.

OpenAI’s report describes how a model under evaluation demonstrated advanced cyber capabilities, and the incident highlighted the need for tighter controls around model evaluation environments and access to external infrastructure. (OpenAI)

This fits into a larger pattern already visible in recent agent evaluations:

The fundamental engineering lesson is simple:

An evaluation environment is still a production security boundary.

Why it matters to you

This is directly relevant to your agent experiments.

When you’re building agents that can:

  • execute Python

  • run shell commands

  • access Git

  • read your vault

  • call APIs

  • manipulate databases

the model isn’t the only risk.

The real system is:

A “trusted” model running with excessive privileges is still an insecure architecture.

This is where your SDET background becomes unusually valuable.

You can test agent systems with:

  • privilege escalation scenarios

  • malformed tool responses

  • credential exposure

  • prompt injection

  • filesystem escape

  • network escape

  • destructive commands

  • recovery after failure
