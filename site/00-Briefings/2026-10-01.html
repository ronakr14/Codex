1. AWS puts DuckDB inside Aurora PostgreSQL — operational + lakehouse data can now meet without ETL

Amazon Web Services announced a particularly interesting capability for Amazon Aurora PostgreSQL: Aurora can now directly query Apache Iceberg and Parquet data in S3, using DuckDB internally. That means an application can combine operational PostgreSQL data with lakehouse data in a SQL query without first copying the lake data into Aurora through an ETL pipeline. AWS says the capability works with Iceberg REST Catalog-compatible catalogs as well as AWS Glue Data Catalog, S3 and S3 Tables. (Amazon Web Services, Inc.)

The important bit is that DuckDB becomes an analytical execution layer inside the operational database boundary. AWS explicitly says future DuckDB improvements can flow into Aurora and other AWS services. (Amazon Web Services, Inc.)

2. Cloudflare launches an Auto Router — model selection is officially becoming an infrastructure control-plane problem

Cloudflare launched Auto Router in public beta for its AI Gateway.

Instead of developers manually choosing a model for every request, Cloudflare’s router classifies the request, estimates task characteristics and selects a model from an eligible pool. Cloudflare reports up to 30% cost savings in its internal OpenCode experiments compared with using frontier models exclusively. (Cloudflare Blog)

The interesting architecture is:

But Cloudflare’s design goes beyond simple classification. It considers cache economics and context switching. Switching models in the middle of a conversation can invalidate useful cache state and force reasoning to be reconstructed, so the router includes a switching penalty based on context size. (Cloudflare Blog)

That’s a genuinely good systems detail.

Why it matters to you

This is almost a mirror image of query optimization:

The future senior AI engineer doesn’t necessarily need to know every model. They need to understand: When should this model run? Why? At what cost? With what context?

That’s architecture.

4. AI coding agents have reportedly exposed 13,000+ internal screenshots — tool permissions are becoming the real attack surface

Security researchers reported that AI coding agents caused more than 13,000 internal screenshots from hundreds of organizations to appear in public GitHub repositories.

The issue wasn’t necessarily that the model itself was “hacked.” Instead, agents performing seemingly reasonable development workflows were given ways to upload screenshots or artifacts into public repositories, creating an unintended data-exfiltration path. (The Hacker News)

5. GitHub’s work on AI coding efficiency reveals a better optimization target: optimize completed work, not token count

GitHub published a detailed engineering write-up on reducing the cost of AI coding agents.

The key lesson is surprisingly subtle:

Fewer tokens doesn’t automatically mean cheaper or faster work.

GitHub found that aggressively shortening tool outputs could cause agents to make additional calls to recover information. Instead, they selectively preserve exact source-like output, reorganize search results without losing information, and compress predictable repetitive logs. (The GitHub Blog)

Their experiments reportedly reduced model-inference costs by roughly 5% offline and around 3% in an online Copilot experiment, without a material regression in tracked quality. (The GitHub Blog)
